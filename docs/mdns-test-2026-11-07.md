# mDNS-Test vom 07.11.2026

Geraet: ESP32-S3, MAC `14:c1:9f:5c:c8:b4`, IP `192.168.31.211`.
Router laut Benutzer: Xiaomi AX3000E, MiWiFi Stabil 1.0.30.
PC-Testadapter: Ethernet, `192.168.31.56/24`; Lanze laut Benutzer im
normalen WLAN. Damit ist der LAN-WLAN-Pfad getestet.

## Durchgefuehrt

- Vorher: API meldet `3.1.2-esp32s3`, Boot-ID `2804173788`.
  Keine Antwort auf die neuen mDNS-Namen, Windows-Namensaufloesung erfolglos.
- `pio run -e esp32s3`: erfolgreich, Flash 827505 Bytes, RAM 105708 Bytes.
- OTA via `upload_firmware.ps1 -DeviceUrl http://192.168.31.211`:
  Firmware verifiziert, automatischer Neustart.
- Nachher: `3.1.3-esp32s3`, Boot-ID `3629679998`.
- Wiederholte DNS-Abfragen per UDP an `224.0.0.251:5353` ueber den
  Ethernet-Adapter, Empfang auf Port 5353 mit Multicast-Gruppenmitgliedschaft.
  Antworten von `192.168.31.211:5353` empfangen.
- A: `messlanze-5cc8b4.local` -> `192.168.31.211`.
- PTR: `_messlanze._tcp.local` ->
  `messlanze-5cc8b4._messlanze._tcp.local`.
- SRV: Ziel `messlanze-5cc8b4.local`, Port 80.
- TXT: `id=14c19f5cc8b4`, `path=/api/current`,
  `firmware=3.1.3-esp32s3`.
- Windows `socket.gethostbyname`: `192.168.31.211`.
- HTTP ueber `http://messlanze-5cc8b4.local/api/current`: Status 200,
  `sensor_ready=true`, `storage_ready=true`, `scd_errors=0`, alle
  Sensor-Validitaetsflags true bei Sequenz 4.

Ergebnis: mDNS und DNS-SD funktionieren zwischen diesem PC und der Lanze
im vorhandenen Netzwerk ohne Routeraenderung.
Ein tatsaechlicher DHCP-IP-Wechsel und ein WLAN-Verbindungsabbruch wurden
nicht ausgeloest; deren Wiedererkennung ist damit noch nicht praktisch getestet.
